# Анализ критических ошибок: `pkg/api/src/services/crm-bot.service.ts`

> Дата анализа: 2026-05-17
> Файл: `pkg/api/src/services/crm-bot.service.ts`

---

## 🔴 1. Уязвимость: захват чужого аккаунта через UID

**Строки:** 191–236

**Проблема:** любой, кто знает 36-символьный `uid` пользователя, может привязать его аккаунт к **своему** Telegram ID, просто отправив UID боту. UID виден в URL публичных квизов, может оказаться в логах или на скриншотах.

**Последствия:** злоумышленник захватывает чужой аккаунт и получает доступ к данным/уведомлениям.

**Решение:** добавить механизм верификации — временный 6-значный код, сессия из web-app, или привязку только из авторизованного web-приложения.

---

## 🔴 2. Ненадёжная проверка UUID — только по длине

**Строка:** 191

```typescript
if (text.length === 36) { // ← любая строка из 36 символов
```

**Проблема:** `findByUid` вызывается для любой строки из 36 символов. Это ложные срабатывания и лишние запросы в БД.

**Решение:** заменить на валидацию формата UUID:
```typescript
const UUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;
if (UUID_REGEX.test(text)) { ... }
```

## 🔴 3. Нет проверки, что сообщение из личного чата

**Строки:** 181, 191

**Проблема:** бот может быть добавлен в группу/канал. Любое сообщение из 36 символов в группе будет воспринято как UID. `chat.id` группы отрицательный, и он запишется в `telegramId` (строка 235).

**Решение:** проверять `message.chat.type === 'private'` или `message.from?.id === message.chat.id`.

---

## 🔴 4. Команда `/start` с параметром не обрабатывается

**Строка:** 181

```typescript
if (text === '/start') { // ← не сработает для "/start ref123"
```

**Проблема:** в Telegram стандартный deeplink: `/start <payload>`. Реферальные ссылки, параметры `startapp` и т.д. ломаются.

**Решение:** использовать `text.startsWith('/start')`.

---

## 🔴 5. `answerCallbackQuery` без `try/catch`

**Строки:** 132–135

**Проблема:** если `answerCallbackQuery` упадёт (сеть, Telegram недоступен), весь callback-обработчик прервётся с throw. Пользователь не получит step 2/3, а бот не ответит на callback.

**Решение:** обернуть в `try/catch`, чтобы ошибка ответа на callback не ломала цепочку онбординга.

---

## 🟡 6. Потеря точности `chat.id` для больших ID

**Строка:** 235

**Проблема:** Telegram ID супергрупп и некоторых пользователей > `Number.MAX_SAFE_INTEGER` (2^53). В `node-telegram-bot-api` `chat.id` приходит как `number`. При `String(message.chat.id)` большой ID может быть уже округлён.

**Примечание:** в вебхуке `telegram/index.ts` `chat.id` валидируется как `t.Number()` — это ещё одна точка потери точности.

---

## 🟡 7. Нет обработки `edited_message`

**Проблема:** пользователь отправляет UID, замечает ошибку, редактирует — бот не реагирует. Для онбординга некритично, но для привязки UID — да.

---

## 🟡 8. Нет rate limiting на привязку UID

**Проблема:** можно брутфорсить UID или флудить запросами `findByUid`. Нет защиты от перебора.
