# Миграция user_payment: добавление истории тарифов

## Описание изменений

Обновлена логика хранения информации о тарифах пользователей. Теперь система поддерживает историю смены тарифов с сохранением всех предыдущих записей.

## Изменения в БД

### 1. Схема таблицы `user_payment`

**Добавлено новое поле:**
- `is_active` (boolean, NOT NULL, default: true) - признак активной записи тарифа

**Удалён constraint:**
- `user_payment_user_id_unique` - уникальность на `user_id` убрана, т.к. у пользователя может быть несколько записей в истории

**Добавлен индекс:**
- `idx_user_payment_is_active` на `(user_id, is_active)` для оптимизации запросов активных тарифов

### 2. Логика переключения тарифов

При смене тарифа через `/payment/:planId`:

1. **Деактивация старых записей**: все записи `user_payment` с `is_active = true` для пользователя устанавливаются в `is_active = false`

2. **Создание новой записи**: создаётся новая запись с `is_active = true` и текущей датой

3. **Учёт собранных ставок** (только для платных тарифов, `plan.price > 0`):
   - Находятся все `quiz_bid` для активных квизов пользователя, где:
     - `quiz.user_id = userId`
     - `quiz.is_active = true`
     - `quiz.deleted_at IS NULL`
     - `quiz_bid.is_full = true`
     - `quiz_bid.is_equal_payment_limit = false`
   - Подсчитывается количество таких ставок
   - Устанавливается `currentLimit` в новой записи `user_payment`
   - Все эти ставки помечаются как `is_equal_payment_limit = true`

## Изменения в коде

### 1. Схема БД (`src/db/user-payment.ts`)
- Добавлено поле `isActive: boolean("is_active").notNull().default(true)`
- Убран `.unique()` constraint с `userId`

### 2. Сервис платежей (`src/modules/payment/service.ts`)
- Метод `updateUserPlan` переработан для поддержки истории тарифов
- Добавлена логика учёта собранных ставок при переключении на платный тариф
- Импортированы `quizTable` и `quizBidTable` для работы со ставками

## Обратная совместимость

⚠️ **Важно**: После применения миграции старая логика с `upsert` по `user_id` больше не работает.

Все существующие записи `user_payment` автоматически получат `is_active = true`.

При первом переключении тарифа после миграции:
- Старая запись деактивируется (`is_active = false`)
- Создаётся новая активная запись

3. ✅ Переключение между платными тарифами
4. ✅ Корректный подсчёт `currentLimit` при переключении на платный тариф
5. ✅ Корректная установка `isEqualPaymentLimit = true` для учтённых ставок
6. ✅ Сохранение истории всех переключений тарифов

## Дополнительная информация

### Схема работы с историей

```
user_payment:
┌────┬─────────┬─────────┬──────────────┬───────────┬────────────┬───────────┐
│ id │ user_id │ plan_id │ created_at   │   limit   │ currentLimit│ is_active │
├────┼─────────┼─────────┼──────────────┼───────────┼────────────┼───────────┤
│ 1  │   123   │    1    │ 2025-01-01   │    100    │     0      │   false   │ ← старая запись
│ 2  │   123   │    2    │ 2025-02-01   │    500    │    45      │   true    │ ← активная
└────┴─────────┴─────────┴──────────────┴───────────┴────────────┴───────────┘
```

### Пример запроса активного тарифа

```typescript
const activePayment = await db
  .select()
  .from(userPaymentTable)
  .where(
    and(
      eq(userPaymentTable.userId, userId),
      eq(userPaymentTable.isActive, true)
    )
  )
  .limit(1);
```
