## Общая информация

### Технологии

- **Bun Test Runner** - для запуска и выполнения тестов
- **Drizzle ORM** - для работы с PostgreSQL базой данных
- **SpyOn/Mock** - для мокирования сервисов (MailService и др.)

### Структура тестов

Все тесты находятся в директории `pkg/api/test/`:

```
test/
├── README.md                          # Этот файл (единая документация)
├── scheduler-payments.test.ts          # Тесты обработки платежей
├── scheduler-payment-methods.test.ts    # Тесты способов оплаты
├── payment-plan-update.test.ts         # Тесты обновления планов
├── s3.service.test.ts                  # Тесты S3 сервиса
├── backup-log.service.test.ts          # Тесты бэкапа логов
├── backup-db.service.test.ts            # Тесты бэкапа базы данных
├── logs/                               # Логи результатов тестов
│   └── YYYY-MM-DD.json
└── utils/
    ├── test-logger.ts                  # Утилита для логирования
    └── test-db.ts                      # Утилиты для работы с БД
```

### Общие требования

- Подключение к PostgreSQL через Drizzle ORM
- Переменные окружения для подключения к БД
- Планы (FREE, BASE, PRO_PLUS) должны существовать в БД
- Для тестов S3 требуются переменные окружения S3 (S3_ACCESS_KEY, S3_SECRET_ACCESS_KEY, S3_BUCKET_NAME)
- Для тестов бэкапа БД требуются `pg_dump` и `gzip` в системе

## Тесты Scheduler

### Обработка платежей

**Файл:** `scheduler-payments.test.ts`

Тесты покрывают функциональность `SchedulerService.processPayments()`, которая обрабатывает платежи пользователей.

#### Покрытые сценарии

##### ✅ 1. Отправка письма за 2 дня до окончания подписки (extended=true)

**Что проверяется:**

- Scheduler находит пользователей, у которых подписка заканчивается через 2 дня
- Отправляется email-уведомление о предстоящем автоматическом списании средств
- Письмо отправляется, если `extended=true` (подписка будет продлена автоматически)

##### ✅ 2. Отправка письма о переходе на FREE план, если extended=false

**Что проверяется:**

- Если `extended=false`, отправляется письмо о том, что платный план закончится и будет действовать бесплатный план FREE
- Это происходит, когда у пользователя есть отложенный платеж (он понизил тариф или не продлевает подписку)

##### ✅ 3. Автоматическое продление подписки после окончания

**Что проверяется:**

- Scheduler автоматически продлевает подписку, если она закончилась
- Обновляет `finalDayAt` на +1 месяц от сегодня
- Сбрасывает лимиты (`limit` обновляется из плана, `currentLimit` = 0)
- Устанавливает `extended=true` и `month=1`

##### ✅ 4. Активация отсроченного плана в день начала (повышение)

**Что проверяется:**

- Scheduler находит отсроченные планы, которые должны начаться сегодня
- Активирует эти планы через `PaymentService.activateScheduledPlan()`
- Деактивирует старый план

##### ✅ 4.1. Активация отсроченного плана (понижение PRO_PLUS -> BASE)

**Что проверяется:**

- Scheduler находит отсроченные планы при понижении тарифа
- Активирует отсроченный план через `PaymentService.activateScheduledPlan()`
- Деактивирует старый более дорогой план

##### ✅ 4.2. Активация отсроченного плана (понижение BASE -> FREE)

**Что проверяется:**

- Scheduler корректно обрабатывает понижение до FREE плана
- Активирует отсроченный FREE план
- Деактивирует старый платный план

##### ✅ 5. НЕ продление подписки, если она еще не закончилась

**Что проверяется:**

- Scheduler НЕ изменяет активные подписки, которые еще не истекли
- `finalDayAt`, `currentLimit` и другие поля остаются без изменений

##### ✅ 6. Обработка нескольких пользователей одновременно

**Что проверяется:**

- Scheduler корректно обрабатывает несколько пользователей в одном запуске
- Для каждого пользователя применяются правильные действия

##### ✅ 7. НЕ отправка письма удаленному пользователю

**Что проверяется:**

- Scheduler игнорирует пользователей с `deletedAt IS NOT NULL`
- Письма НЕ отправляются удалённым пользователям

##### ✅ 8. НЕ обработка бесплатного плана

**Что проверяется:**

- Scheduler обрабатывает только платные планы (`planId != 1`)
- Пользователи с бесплатным планом игнорируются

##### ✅ 9. Установка правильного лимита для Pro+ с дополнительным лимитом

**Что проверяется:**

- Scheduler правильно восстанавливает лимиты для Pro+ плана с учётом дополнительного лимита (upLimit)
- При продлении подписки учитывается базовый лимит из плана + дополнительный лимит из `user_payment_pro`

### Обработка способов оплаты

**Файл:** `scheduler-payment-methods.test.ts`

Тесты проверяют обработку различных способов оплаты (crypto_pay, card, bank_transfer) в scheduler.

#### Покрытые сценарии

##### ✅ 1. Обработка crypto_pay: создание платежа и отправка письма со ссылкой

**Что проверяется:**

- При истечении подписки с crypto_pay scheduler создаёт платёж
- Отправляется письмо со ссылкой на оплату
- Счётчик попыток увеличивается

##### ✅ 2. Обработка crypto_pay: повторная отправка письма при существующем платеже

**Что проверяется:**

- При повторной обработке используется существующий платёж
- Отправляется письмо с той же ссылкой на оплату
- Счётчик попыток увеличивается

##### ✅ 3. Перевод на FREE план после превышения максимального количества попыток (crypto_pay)

**Что проверяется:**

- После 7 неудачных попыток оплаты пользователь переводится на FREE план
- Подписка деактивируется
- Отправляется уведомление о переводе на FREE план

##### ✅ 4. Обработка card: попытка списания средств (неудачная)

**Что проверяется:**

- При истечении подписки с card scheduler пытается списать средства
- Если списание не удалось, увеличивается счётчик попыток
- Подписка остаётся активной до превышения лимита попыток

##### ✅ 5. Перевод на FREE план после превышения максимального количества попыток (card)

**Что проверяется:**

- После 7 неудачных попыток списания с карты пользователь переводится на FREE план
- Логика аналогична crypto_pay

##### ✅ 6. Пропуск попытки списания вне временных рамок 00:00-02:00 (РЕАЛИЗОВАНО)

**Что проверяется:**

- Попытки списания для способов оплаты `card` и `bank_transfer` выполняются только в период 00:00-02:00
- Вне временных рамок попытки списания пропускаются с логированием
- В тестах проверка времени может быть пропущена через параметр `skipTimeCheck: true`

**Технические детали:**

- Scheduler запускается через `@elysiajs/cron` каждые 20 минут в период 00:00-02:00
- Внутри `processPayments()` есть дополнительная проверка времени через `DateUtils.isWithinHourRange(0, 2)`
- Для способов оплаты `crypto_pay` временные рамки не применяются

# Запуск с детальным выводом

- Переменные окружения S3 (S3_ACCESS_KEY, S3_SECRET_ACCESS_KEY, S3_BUCKET_NAME)
- Переменные окружения для подключения к PostgreSQL (DATABASE*URL или POSTGRES*\*)

## Реализованная функциональность

### Scheduler Service

#### ✅ Все задачи scheduler переведены на @elysiajs/cron

**Статус:** Все задачи scheduler теперь запускаются через `@elysiajs/cron`

**Реализованная функциональность:**

- ✅ Все задачи scheduler переведены с `setInterval` на `@elysiajs/cron`
- ✅ Обработка незавершенных заявок: каждую 1 минуту (cron: `*/1 * * * *`)
- ✅ Обработка платежей: каждые 20 минут в период 00:00-02:00 (cron: `0,20,40 0-1 * * *` и `0 2 * * *`)
- ✅ Graceful shutdown корректно останавливает все cron jobs через `store.cron`
- ✅ Убраны все `setInterval` из кода scheduler

**Технические детали:**

**Обработка незавершенных заявок (`processIncompleteBids`):**

- Cron паттерн: `*/1 * * * *` (каждую 1 минуту)
- Имя cron job: `processIncompleteBids`
- Задача: обработка незавершенных заявок для платных пользователей

**Обработка платежей (`processPayments`):**

- Cron паттерн основной: `0,20,40 0-1 * * *` (каждые 20 минут в часы 0 и 1: 00:00, 00:20, 00:40, 01:00, 01:20, 01:40)

- Имена cron jobs: `processPayments` и `processPaymentsLastAttempt`
- Дополнительная проверка времени внутри функции для точного контроля (00:00-02:00)
- В тестах проверка времени может быть пропущена через параметр `skipTimeCheck: true`
- Всего выполняется 7 попыток: 00:00, 00:20, 00:40, 01:00, 01:20, 01:40, 02:00

**Преимущества использования cron:**

- Более надежное планирование задач
- Возможность остановки через `store.cron.jobName.stop()`
- Лучшая интеграция с Elysia lifecycle
